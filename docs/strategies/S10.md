# S10 — Copy trading filtrado

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V8. Mercado:Wallets Solana observables. Horizonte:1 min–4 h.

## Hipótesis económica

Algunas decisiones públicas pueden conservar ventaja después de retraso del follower.

## Datos y dependencias

Wallet fills, selección train, inventario/cobertura y quote nueva. Componentes: C-TRADERS,C-EXEC. Entradas `FeatureSnapshot`, `PortfolioView`, `StrategyConfig`; salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

Wallet previamente elegida y coverage>=0,95; señal de compra recibida; nueva quote; rechazar si precio ya avanzó>2% o edge no cubre costos. Tamaño del follower lo fija Risk.

Parámetros iniciales preregistrables:

```json
{
  "coverage_min": 0.95,
  "max_chase_bps": 200,
  "hold_s": 1800
}
```

## Salida y riesgo

Salida pública recibida o30 min; límites propios y reversión.

Riesgos particulares: No observar hedge, inventario inicial o acceso privilegiado; latencia adversa. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Follower no usa precio líder; wallets aleatorias emparejadas y cohortes ganadoras/perdedoras. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.
