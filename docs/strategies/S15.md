# S15 — Arbitraje

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V9. Mercado:DEX atómico primero; cross-venue futuro. Horizonte:subsegundos–segundos.

## Hipótesis económica

Diferencia executable después de todas las piernas puede superar costos.

## Datos y dependencias

Quotes simultáneas, capacidades de atomicidad, balances y fees. Componentes: C-EXEC,C-LAB. Entradas `FeatureSnapshot`, `PortfolioView`, `StrategyConfig`; salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

Comparar ida/vuelta para mismo tamaño; enviar sólo bundle de transacción atómica decodificada con min_profit>cost+buffer. Cross-venue no atómico sólo paper y exposición de leg explícita.

Parámetros iniciales preregistrables:

```json
{
  "quote_skew_ms": 200,
  "buffer_bps": 20
}
```

## Salida y riesgo

Fin de ciclo; fallo atómico contabiliza fees; leg residual paper se liquida con coste estresado.

Riesgos particulares: Quotes asincrónicas, MEV, bridge/counterparty y capital inmovilizado. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Simular una pierna falla, expira quote y cambio de reservas; rechazar sin atomicidad certificada. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.
