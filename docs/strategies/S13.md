# S13 — Grid

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V9. Mercado:CLOB spot líquido. Horizonte:horas–días.

## Hipótesis económica

Oscilaciones en rango pueden compensar costos si no hay tendencia dominante.

## Datos y dependencias

L2, tick/lot, balances y régimen lateral. Componentes: C-EXEC,C-LEDGER. Entradas `FeatureSnapshot`, `PortfolioView`, `StrategyConfig`; salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

Cinco niveles simétricos alrededor de mid congelado, spacing=max(50bps,2×costo roundtrip); cotizar compras/ventas sólo con inventario propio y reserva por orden. Sin aumentar tamaño tras pérdida.

Parámetros iniciales preregistrables:

```json
{
  "levels": 5,
  "spacing_bps": 50,
  "hold_s": 86400
}
```

## Salida y riesgo

Ruptura de rango2×ancho, límite de inventario o24 h; cancelar/reconciliar.

Riesgos particulares: Inventario en tendencia, cancel race, fees y cola. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Trayectoria monotónica debe perder/controlar y parar; fills conservadores y cancel parcial. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.
