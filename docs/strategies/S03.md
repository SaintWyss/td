# S03 — Scalping

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V9. Mercado:Solana pools soportados o CLOB. Horizonte:5–60 s.

## Hipótesis económica

Microflujo puede predecir cambios muy cortos si latencia/costos dejan margen.

## Datos y dependencias

Trades subsegundo/segundo, depth o reservas, quotes, latencia empírica. Componentes: C-EXEC,C-LAB. Entradas `FeatureSnapshot`, `PortfolioView`, `StrategyConfig`; salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

Cada segundo, desequilibrio de volumen comprador/vendedor10 s>0,3 y microretorno positivo; entrada sólo si edge neto inferior95%>0 y delay p99<horizonte/5.

Parámetros iniciales preregistrables:

```json
{
  "window_s": 10,
  "imbalance_min": 0.3,
  "hold_s": 10
}
```

## Salida y riesgo

Reversión de imbalance a<=0 o10 s; cap inventario y quote vigente.

Riesgos particulares: Competencia/MEV; datos agregados minuto son inadmisibles. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Replay por evento con latencias1×/2×/5×; rechazar si no conserva ventaja estresada. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.
