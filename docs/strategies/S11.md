# S11 — Smart-money agregado

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V8. Mercado:Solana spot. Horizonte:5 min–4 h.

## Hipótesis económica

Flujos conjuntos de wallets elegidas ex ante pueden ser informativos.

## Datos y dependencias

Perfiles PIT, clusters de dependencia y flows. Componentes: C-TRADERS,C-LAB. Entradas `FeatureSnapshot`, `PortfolioView`, `StrategyConfig`; salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

Tres clusters independientes seleccionados en train con entradas netas en 5 min; long sólo si score de cohortes>percentil80 train y quote apta.

Parámetros iniciales preregistrables:

```json
{
  "window_s": 300,
  "min_clusters": 3,
  "score_percentile": 80,
  "hold_s": 3600
}
```

## Salida y riesgo

Flujo neto negativo o1 h.

Riesgos particulares: Clusters pueden ser mismo operador; score no prueba intención. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Ablación de wallet-score, selección aleatoria y exclusión de cluster dominante. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.
