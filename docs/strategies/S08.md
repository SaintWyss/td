# S08 — Noticias

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V9. Mercado:Spot cubierto por fuente autorizada. Horizonte:5 min–4 h.

## Hipótesis económica

Un evento novedoso verificable puede no estar completamente incorporado al precio recibido.

## Datos y dependencias

News permitida, published/received/available, entidad resuelta y quotes. Componentes: C-RESEARCH,C-AI. Entradas `FeatureSnapshot`, `PortfolioView`, `StrategyConfig`; salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

Clasificar evento predefinido, dos orígenes independientes o comunicado primario; dirección positiva y entidad inequívoca; ejecutar después deavailable_at con decay exponencial60 min.

Parámetros iniciales preregistrables:

```json
{
  "decay_s": 3600,
  "hold_s": 3600,
  "min_independent_sources": 2
}
```

## Salida y riesgo

Caducidad60 min, corrección de noticia o caída de tesis.

Riesgos particulares: Rumor, duplicación, timestamp editado, prompt injection. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Ablación sin noticia y timestamps desplazados; corpus evaluado por humanos; impedir rumor sin contraste. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.
