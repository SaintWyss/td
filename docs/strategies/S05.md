# S05 — Breakout

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V9. Mercado:Solana/spot líquido. Horizonte:5–60 min.

## Hipótesis económica

Ruptura con volumen puede indicar persistencia de demanda.

## Datos y dependencias

Barras cerradas1 min, volumen, costos y profundidad. Componentes: C-LAB,C-RISK. Entradas `StrategyInput` 1.2 (contexto tipado según catálogo R2); salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

close_t>max(high de 20 barras anteriores) y volume_t>1,5×mediana previa; excluir la barra actual del canal.

Parámetros iniciales preregistrables:

```json
{
  "channel_bars": 20,
  "volume_ratio": 1.5,
  "atr_mult": 2.0,
  "hold_s": 1800
}
```

## Salida y riesgo

Retorno bajo nivel de ruptura, trailing2×ATR20 o30 min.

Riesgos particulares: Falso breakout, gaps y costo de perseguir movimiento. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Fixture que detecta leakage de incluir high actual; comparar breakout sin volumen. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.

## Especificación de entradas y oracle R2 — 1.2.0

Contrato canónico: `../contracts/strategy-specs.json`, entrada `S05`; catálogo `../contracts/feature-catalog.json`. Instrumentos: AMM_POOL,CEX_SPOT. Horizonte efectivo: 1800 s. Ventanas fijas del catálogo 1.2; cambiar una ventana requiere nueva definición y versión.

Features obligatorias: F-close1, F-high20, F-volume_ratio20, F-atr20, F-drawdown_peak, F-cost_bps. Opcionales: ninguna en esta versión. Contexto adicional: bars,memory. Datos mínimos: 21 complete minute bars; entry level and peak persisted in StrategyMemory.

Regla operativa precisa (prevalece sobre el resumen anterior): BUY iff close>prior high20 and volume_ratio20>1.5. Store breakout_level=high20. SELL when close<stored level, executable price<=peak-2*atr20 or age>=1800. Update peak only with received executable quote.

Oracle STR-S05: close=102,prior_high=101,ratio=1.6,ATR=1 → **BUY**. Cálculo independiente: 102>101,1.6>1.5; including current high102 incorrectly prevents entry. El resultado es una propuesta pura, no una orden.

Experimento específico: Prior-channel exclusion fixture; compare breakout without volume; gap stress. Las condiciones científicas originales siguen vigentes; no hay rentabilidad demostrada.
