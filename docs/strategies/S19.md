# S19 — Gestión dinámica de salida

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V5. Mercado:Posiciones spot. Horizonte:evaluación1 s–1 min.

## Hipótesis económica

Salida basada en riesgo/liquidez puede limitar exposición aunque no garantice ejecución.

## Datos y dependencias

Posición, quote inversa, tiempo, riesgo actual y señal. Componentes: C-RISK,C-EXEC. Entradas `FeatureSnapshot`, `PortfolioView`, `StrategyConfig`; salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

No abre. Prioridad: riesgo crítico→intentar cierre seguro; luego tiempo máximo, stop observado, trailing, reversión. Reduce-only verdadero, nunca vende más que balance disponible.

Parámetros iniciales preregistrables:

```json
{
  "trailing_bps": 500,
  "max_hold_s": 1800
}
```

## Salida y riesgo

Finalizada sólo después de fill/reconciliación; sin ruta marca UNLIQUIDATABLE.

Riesgos particulares: Gap salta stop; datos de alpha viejos no reemplazan quote válida; fee SOL insuficiente. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Quote desaparece, doble evento de cierre, pending previo y balance menor al solicitado. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.
