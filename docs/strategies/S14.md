# S14 — Market making

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V9. Mercado:CLOB autorizado. Horizonte:segundos–minutos.

## Hipótesis económica

Spread capturado puede superar adverse selection y fees con inventario controlado.

## Datos y dependencias

L2 íntegro, trades, maker/taker fees, latencia y tick/lot. Componentes: C-EXEC,C-RISK. Entradas `FeatureSnapshot`, `PortfolioView`, `StrategyConfig`; salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

Cotizar bid/ask a mid±max(2 ticks,1,5×fee_equiv), skew alejando lado que aumenta inventario; post-only cuando capability certificada.

Parámetros iniciales preregistrables:

```json
{
  "min_ticks": 2,
  "fee_mult": 1.5,
  "requote_ms": 2000
}
```

## Salida y riesgo

Cancelar/requote cada 2 s o mid mueve1 spread; detener ante inventario/gaps.

Riesgos particulares: Toxic flow, cola, cancel/replace, doble fill y exchange outage. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Modelo de cola independiente y worst-case doble fill; comparar no cotizar en volatilidad. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.
