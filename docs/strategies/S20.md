# S20 — Selección por regímenes

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V9. Mercado:Metapolítica de estrategias aprobadas. Horizonte:actualización15 min.

## Hipótesis económica

El desempeño relativo de estrategias puede depender de volatilidad/tendencia/liquidez.

## Datos y dependencias

Features de régimen PIT y retornos OOF de estrategias. Componentes: C-ML,C-STRATEGY. Entradas `FeatureSnapshot`, `PortfolioView`, `StrategyConfig`; salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

Clasificar con umbrales train congelados de volatilidad/tendencia; seleccionar estrategia aprobada con mayor utilidad conservadora por régimen; si ninguna cumple NO_TRADE. Histeresis2 ventanas.

Parámetros iniciales preregistrables:

```json
{
  "interval_s": 900,
  "hysteresis_windows": 2
}
```

## Salida y riesgo

Cambio confirmado de régimen sólo afecta nuevas entradas; salidas siguen política activa.

Riesgos particulares: Leakage del selector, alta rotación y sobreajuste de regímenes. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Comparar pesos fijos, selector aleatorio y simple siempre-momentum; contar todos los trials. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.
