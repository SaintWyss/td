# S07 — Order-flow imbalance

Estado: SPECIFIED; sin rentabilidad demostrada. Fase:V9. Mercado:CLOB con L2. Horizonte:1–30 s.

## Hipótesis económica

Desequilibrio de liquidez/flujo puede anticipar cambio del mid.

## Datos y dependencias

L2 snapshot+deltas íntegros, trades y checksum. Componentes: C-DATA,C-LAB. Entradas `StrategyInput` 1.2 (contexto tipado según catálogo R2); salida `Signal` o abstención explícita. Incluir timestamps propios, cobertura y evidencia. Datos insuficientes bloquean sólo esta familia.

## Algoritmo y entrada

I=(sum bidqty top5−sum askqty top5)/(suma total); long si I>0,6 durante3 updates y flujo comprador neto5 s>0; bloquear checksum inválido.

Parámetros iniciales preregistrables:

```json
{
  "depth_levels": 5,
  "imbalance_min": 0.6,
  "confirm_updates": 3,
  "hold_s": 10
}
```

## Salida y riesgo

I<0 o10 s; bid ejecutable y fees.

Riesgos particulares: Spoofing/cancelaciones; qty agregada no garantiza fill pasivo. Hereda el motor de riesgo; no puede aumentar caps, ignorar una fuente vieja o saltar reservas. Instrumentos sin capacidad requerida devuelven `UNSUPPORTED_VENUE`.

## Costos y restricciones

Evaluar comisiones de entrada/salida, spread/impacto, slippage, latencia, fills fallidos/parciales según venue, fees de red y rent aplicable. Funding/borrow sólo para familias que los requieren. No duplicar fees ya incluidas en quote. No abrir si el costo conservador elimina el margen. Long-only spot y sin apalancamiento en MVP; derivados/CLOB avanzados permanecen sandbox hasta certificación específica.

## Experimento y pruebas

Deltas fuera de orden, cola conservadora, spoof-like cancel; DeepLOB opcional sólo challenger. Prueba unitaria para cada umbral justo por debajo, igual y por encima; entrada futura, NaN, cero denominador y serie insuficiente deben abstenerse. Integración replay→riesgo→paper con salida y journal balanceado. Validar permiso de fuente y ausencia de efectos de red desde estrategia.

## Aceptación o rechazo

Aceptación técnica: coincide con los fixtures y contrato, conserva invariantes, no usa información futura y explica abstenciones. Aceptación científica: G-DATA/G-LAB y, para promoción, G-PAPER; intervalo neto positivo y mejora emparejada después de selección múltiple. Rechazo si el mecanismo no sobrevive costos, placebo o cambio de régimen; INCONCLUSIVE si muestra/cobertura insuficiente. No se ajustan parámetros después de ver holdout sin nueva versión/ensayo.

## Implementación

El backlog contiene dos tareas separadas: evaluador puro y experimento/falsación. Las dependencias de datos/venue se certifican antes; no crear un simulador ficticio para completar una tarea. Evidencia: fixture, config hash, dataset manifest, comandos, salida y verdict aun si es REJECTED.

## Especificación de entradas y oracle R2 — 1.2.0

Contrato canónico: `../contracts/strategy-specs.json`, entrada `S07`; catálogo `../contracts/feature-catalog.json`. Instrumentos: CEX_SPOT. Horizonte efectivo: 10 s. Ventanas fijas del catálogo 1.2; cambiar una ventana requiere nueva definición y versión.

Features obligatorias: F-book_i5, F-flow5, F-spread_bps. Opcionales: ninguna en esta versión. Contexto adicional: books. Datos mínimos: 3 consecutive valid contiguous L2 updates with5 levels each, complete5s trade flow.

Regla operativa precisa (prevalece sobre el resumen anterior): BUY iff each last3 book_i5>.6 and flow5>0. Held SELL if current I<0 or age>=10s; gap/checksum failure => ABSTAIN and cancel proposals, not assume fills.

Oracle STR-S07: last3 I=.7,.65,.8; signedflow=.2 → **BUY**. Cálculo independiente: top5 bids90 asks10 gives .8; one missing update invalidates confirmation. El resultado es una propuesta pura, no una orden.

Experimento específico: Adversarial cancels/spoof-like depth, conservative queue; compare flow-only model. Las condiciones científicas originales siguen vigentes; no hay rentabilidad demostrada.
