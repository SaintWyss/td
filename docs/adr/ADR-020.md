# ADR-020 — Catálogo temporal y estimandos separados

Estado: ACCEPTED_DESIGN. Fecha: 2026-11-06. Scope: GD-11, contratos1.2 preimplementación.

Problema: StrategyInput no representaba entradas para20 familias, FeatureValue tenía nombre
libre y Prediction obligaba probabilidad y retornos para cualquier modelo. Las ventanas y
contextos faltantes obligaban a inventar reglas durante implementación.

Decisión: catálogo canónico de features con fórmula/fuente/unidad/ventana/permiso/PIT; StrategyInput
con contextos tipados y contrato individual para cada estrategia. CLASSIFICATION, REGRESSION y
RETURN_DISTRIBUTION no comparten estimando implícito. Decision usa evidencia neta y nunca convierte
scores en probabilidad o tamaño. S13 fija5 niveles por lado; S18 requiere61 barras para un cruce;
S20 selecciona sin ejecutar; state/memory se persiste fuera del evaluador puro mediante CAS.

Consecuencias: migración incompatible de fixtures, OpenAPI y eventosv2; no hay consumidores
desplegados. Nuevas fuentes normalizadas no acreditan un proveedor/licencia. Derivados y CLOB
continúan sandbox, estrategias deshabilitadas y live no autorizado. R1 se conserva como historia.

Alternativas descartadas: map<string,float> con nombres libres y StrategyInput sólo snapshot;
introducir futuro precio/return para completar fixtures; habilitar todas las familias al tiparlas.

Referencias: ../contracts/features-and-strategies.md, feature-catalog.json y strategy-specs.json.
