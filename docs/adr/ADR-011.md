# ADR-011 — Validación temporal y multiplicidad

Estado: ACCEPTED para diseño, pendiente de implementación. Fecha:2026-11-03. Responsable de cambios: propietario técnico.

## Contexto

Muchas pruebas pueden fabricar un ganador aparente.

## Decisión

Preregistro, nested temporal, holdout único, bootstrap y control familiar.

## Alternativa descartada

Random split y reporte sólo del mejor Sharpe inflan evidencia.

## Consecuencias y verificación

Registrar ensayos negativos y rechazar resultado inconcluyente. La tarea correspondiente debe aportar prueba positiva y negativa, fixture reproducible y revisión de compatibilidad antes de integrar. Si el supuesto cambia, crear ADR que superseda éste; no modificarlo silenciosamente.
